固定 `D:\agentdock-poc-20261010\runtime\agentdock.exe`，已验证 v1.0.1 / FileVersion 1.0.1.0，SHA-256：

```text
bc1a7a35f1985e9f7827142577fc31bd4ca536e27252b08fc28c5ed636cf5e8d
```

启动前复检 hash、DACL、上一运行的 guardian/Job 完成证据及端口。占用者保留原状；重复启动拒绝。新进程只有在 guardian 已将 supervisor 纳入 Job 后才启动子进程。启动成功要求无 Bearer 的 MCP 401、正确 Bearer 的 MCP initialize/固定工具 schema，以及 Tong discovery 与未鉴权 MCP 401；端口可连接不等于健康。

DevSpace/Gateway 在 IPC 配置发送后各有 20 秒就绪期限，整体启动仍有 30 秒健康期限；lifecycle 记录每阶段耗时和白名单失败代码。独立候选首次触发原 10 秒内部期限，失败 Job=0，证据保留；增加阶段记录并调整期限后，同一候选的真实 CLI/子进程验收通过。这不是取消启动期限或增加自动重试。

`status` 不删除失效 PID、旧请求或锁记录。`doctor` 执行本机鉴权/协议探测，不启动服务。停止先断开 Gateway、等待 DevSpace/Tong cleanup，之后仅核对和终止直接受管进程；所有后代由私有 Job 清理。终止使用同一 Windows handle 校验 exe/创建时间并调用 TerminateProcess，避免 PID 被复用后的误杀；后代 PID 快照仅用于诊断，并复检创建时间链，不作为单独终止依据。

停止完成同时要求记录状态、guardian 已退出、Job 活跃成员数为零和 supervisor 身份消失。不能仅凭端口释放或 Tong cleanup 返回判断全部子进程已死。启动超时写入对应 runId 的 abort，由 guardian 撤销该 Job；不能证明清理完成时返回 `CLEANUP_REQUIRED` 并保留 freeze 阻止后续启动/备份，不自动删锁重试。没有自动重启或执行任务重放。

DACL 检查只允许当前 Rune SID、SYSTEM、Administrators 的 Allow ACE，要求非空、canonical DACL、合法 owner，并拒绝符号链接、junction/reparse 和文件 hardlink。子目录继承已保护父目录；子目录本身不必逐个关闭继承。普通 Authenticated Users/Users ACE 会导致拒绝，不能用 `mode:0o600` 代替 Windows DACL。

实际 Windows `AuthzAccessCheck` 使用合成普通 SID，附加 Authenticated Users、Users、Everyone：policy/journal/audit 文件的 WRITE_DATA、DELETE、WRITE_DAC 均拒绝；原宽权限 `isolated` 父目录正向对照确实允许写入。**没有创建账户或进行真实第二用户登录**；这是 Windows 授权引擎对合成身份的实测。当前运行账户、SYSTEM 和管理员仍可更改文件；这不是对同账户恶意程序的隔离。

DPAPI 使用 [CurrentUser](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.dataprotectionscope)，校验 userSid/purpose/schema，加用途 entropy。Token 由 stdin 在内存送至保护 helper；解密只经仅当前用户/SYSTEM/Admin 可访问的随机命名管道返回 Node，不经 argv、stdout 或 stderr。密文 create-only；密文被损坏或身份不符时拒绝，不替换或自动生成新 Token。备份只允许已知格式的 DPAPI 密文，伪装密文和明文秘密文件均被拒绝。

guardian/supervisor/Gateway 不持有 Token 环境变量；解密值仅在 supervisor 内存及必要 IPC 中流转。AgentDock 环境只有所需后端 Token，DevSpace 只得到所需后端 Token 和内存 owner 配置；Gateway 与其他受管子进程使用 allowlist 环境。真实 AgentDock Windows 命令子进程也已验证没有 `AGENTDOCK_AUTH_TOKEN`、`TONG_AGENTDOCK_TOKEN`、`OAUTH_OWNER_TOKEN`。后端 stdout/stderr 通过跨 chunk 的 Token 脱敏流写入保护目录，测试逐文件确认没有两项测试 Token。

没有读取现有生产 Token。DPAPI 备份不能承诺在另一机器/用户下解密；跨身份恢复失败应阻塞启动并另行批准凭据恢复，不能覆盖旧密文。DevSpace 原 OAuth SQLite 仍遵循自身数据格式；本次并未给生产 OAuth 行增加 DPAPI 加密或迁移。

## 可执行备份与恢复

入口为 `node scripts/TongRuntimeBackup.mjs backup|verify|restore|restore-code ABSOLUTE_JSON_CONFIG`。配置文件必须在保护目录内；不接收动态 Shell、真实凭据或生产路径。需要先显式 stop，核对所有 owned 身份、guardian 结束和 Job=0；启动与备份共用 create-only `run/backup.freeze`，其他实例不能并发修改同一源。

`backup` 配置字段：`sourceRoot`、新的 `backupRoot`、开发 `codeRoot`、固定 `codeCommit`、绝对 `gitExecutable`、绝对 `pythonExecutable`。演练使用本机 bundled Git 和 `C:\Program Files\Python311\python.exe`。`verify` 只需 `backupRoot`。`restore` 字段为 `backupRoot`、新的 `restoreRoot`、`pythonExecutable`、`journalFloorRoot`。`restore-code` 字段为 `backupRoot`、新的 `codeRestoreRoot`、`pythonExecutable`、`npmCli`（本机 `D:\node\node_modules\npm\bin\npm-cli.js`），可选保护目录 `npmCacheRoot`。

已执行顺序：

1. 新合成实例放置项目登记、有效 demo read grant、审批、queued/running 任务、审计、未知结果 journal、DPAPI 密文、模拟 OAuth/schema 与有未 checkpoint WAL 的 SQLite。记录 stopped；没有复制真实数据。
2. 冻结源，复制文件和 WAL/SHM，归档 Git 版本/lock/patch/原生资产；源前后 inventory 一致才完成 manifest。SQLite 只打开副本验证，不 checkpoint 原源库。
3. 核对文件清单/hash、SQLite integrity/schema/逻辑 hash；损坏或额外链接/文件拒绝。
4. 在原源新增备份后的操作 key；恢复必须读取这个**原始最新源**作 journal floor，与 `manifest.sourceRoot` 绑定，不能使用备份内部 runtime、旧快照或另一个恢复目录。源不可用时阻塞恢复，不假设旧快照拥有最新 keys。
5. 新目录复制快照，add-only 合并 floor。冲突拒绝；旧 key 和备份后 key 均实际调用 `reserveAgentDockOperation` 得到 REPLAY_DENIED。
6. 恢复清空 AgentDock projects/approvals、execution grants、trusted 授权；登记项目 disabled，旧 queued/running/waiting 状态 failed 并标记需对账，取消旧 session/pendingApproval。默认 demo 的原 read grant也被清空，实际 resolver 拒绝。旧任务不会自动启动。
7. 独立代码目录恢复精确 b967958、锁依赖、对应 native 和 patch，`--check`、SQLite native load 通过。恢复过程没有启动任何任务或服务。

当前 `restore-code` 固定的是本次要求的 b967958 基线。已另外归档完整 B2.2 源码及运行管理/审计 override，并封装到独立候选，保留 Git commit 与逐文件 hash；正式部署必须同时保存这一层，不能只恢复 b967958 archive 就声称运行器也已经恢复。本轮没有把合成工具扩展为生产路径/任意版本恢复器。恢复目录的 `profile.tongRoot` 需要显式绑定已核验的候选代码目录后再由操作者启动，不能沿用旧路径自动启动。

原始快照保留旧审批和任务证据供本机对账；运行恢复副本不复活这些权限。manifest/hash 用于完整性核对，不是抵御同账户或管理员同时改写 manifest 的签名机制。最新 journal floor 丢失、冲突或无法确定谱系时必须停止，不自动换 key 重新派发。
