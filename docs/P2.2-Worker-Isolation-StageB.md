# P2.2 Windows Worker 隔离：阶段 B 审批清单

## 状态

阶段 A 已完成代码、模拟测试和临时 canary 探针。P2.2-B0 增加可构建的 Windows 原生 Supervisor、命名管道桥、受限令牌/Job 启动、ACL 恢复日志及合成集成测试。真实 Worker 启动器仍未接入 MCP；MCP 中真实 Codex 执行保持关闭。账户、服务和真实 ACL 均未更改。

## B0.1 LPAC 最后一轮合成验收（未完成）

当前 LPAC 实验不能作为安全修复或阶段 B 验收结论。基线合成测试曾证实：restricting SID 列表包含 Everyone、Users、Authenticated Users 时，项目外对象只要 DACL 对这些 SID 授权，restricted-token 的第二次访问检查仍会允许访问。最后一轮将边界改为 LPAC 后，实际 Worker 对项目外 `Everyone: Read`、`Users: Modify` 和 `Authenticated Users` canary 的读、写、删探针均返回拒绝；项目内读、写、删通过。测试还检查了 All Application Packages 与 All Restricted Application Packages canary，但最终摘要中这两组的汇总字段为空，不能据此记为通过。

同一轮的 Node、Git、Python、Codex `--version` 子进程探针均以退出码 0 结束。这只证明这些版本命令能启动，不证明真实 Codex 任务或完整工具工作流正常。LPAC 主 Worker 已启动、token 检查返回通过并被放入 Job；但模拟 Worker 启动的 Node 子进程退出码为 1，`child.json` 未生成，集成断言因此失败。后续子进程权限、Job 关闭/取消/超时清理、超时后进程计数、命名管道恶意 peer、HMAC 负向用例及 ACL 崩溃恢复/外部变更冲突检查没有在这轮运行中到达。测试没有因此放宽任何项目外 DACL。

剩余权限风险：当前 `CreateRestrictedToken` 不再设置任务 restricting SID 列表；任务 SID 虽仍被写入项目 ACL，但它没有参与第二次访问检查。AppContainer 名称目前也不是每任务唯一。因此不能证明项目临时 ACL 与任务 SID 构成有效的逐任务权限边界。LPAC 的组 canary 拒绝结果不弥补这一点，也不能证明独立账户下的隔离。不要把当前原生 Worker 接到 MCP、不要启用真实 Worker，也不要开始阶段 B。

当前 ACL/IPC 证据范围：合成运行在正常请求中启动并处理了固定管道客户端；测试在启动集成前还观察到 Supervisor 持锁时并发 ACL journal 写入被拒绝，且项目 DACL 未变。代码把已打开的客户端进程句柄用于 token 与映像核验，并通过同一已连接管道的 `RunAsClient` token 对照后才读取请求；这轮没有到达专门的伪造 peer 负向断言。请求路径会记录原 DACL、先写 journal、结束后按当前 DACL 与文件身份核对再恢复；异常退出恢复和外部 DACL 变更冲突保护仍需合成运行验证。若 Job 清理失败，ACL journal 必须保留并阻止后续任务，不能通过强制覆盖外部 DACL 来恢复。

阶段 B 的独立账户验收仍须等到合成环境同时证明：项目外广泛授权被拒、按任务区分的项目访问确实生效、Node/Git/Python 实际操作可用、所有子进程都受同一 Job 控制并在关闭/取消/超时后归零、命名管道身份验证与读取绑定在同一连接、journal 在崩溃/外部变更/并发下安全恢复。之后才可在单独授权下创建独立账户并使用合成目录复测；本次没有创建账户、服务或修改真实 ACL。

推荐方案：单独的标准本地账户 `TongCodexWorker` 承载 Windows 服务 `TongWorkerSupervisor`。Gateway 必须先具备与普通交互用户 SID 不同的专用服务 SID；原生服务在命名管道 ACL 之外核对该 SID、客户端 PID、映像路径和 SHA-256，桥接进程反向核对服务 PID、账户 SID、映像路径和 SHA-256。Supervisor 对每个任务创建 restricted token 和独立 Job Object；Codex、Git、Node、Python 及其全部子进程都在该 token 和 Job 中运行。每次只向一个已授权项目和任务临时授予 ACL，任务结束或取消后撤销。

`Authenticated Users` 在 Worker 令牌的普通访问检查中设置为 deny-only，用来中和当前 D: 目录树继承的 `Authenticated Users: Modify`。受限 SID 的第二次访问检查用于确认 Worker 账户、任务 SID 或已检查的只读系统依赖确实获准。Supervisor 是可信计算基的一部分，只接受固定任务协议，不提供 Shell、任意命令或任意路径接口。

## 阶段 A 完成项

- `TongWorkerBroker` 在执行前重新验证 `agent.execute`、已注册项目根路径和隔离状态。缺少已验证的隔离检查或启动器时直接拒绝；没有回退到 Gateway 身份的分支。
- Worker 消息使用 v1 精确字段协议、每次任务随机 32 字节 HMAC 密钥、最大帧大小和任务 ID 绑定。密钥由启动器通过私有启动通道提供；任务正文和授权根路径只通过私有 IPC 发送。
- Worker 只接收注册项目根目录，不接受客户端 executable、命令行或环境变量。启动器需要提供完整的进程/Job 会话，否则已创建的 Job 会先终止并关闭。
- Worker 验证实际隔离快照、固定绝对 Codex 可执行文件及 SHA-256、隔离环境和日志脱敏。没有身份探针时安全失败。
- stdio IPC 覆盖有效任务、伪造签名拒绝、任务取消和错误回传；任务管理器覆盖权限撤销、持久状态、取消隔离和错误恢复。
- `tests/Test-TongWorkerCanaries.ps1` 在 `%TEMP%` 下创建隔离 canary。使用当前进程派生的 restricted token、临时限制 SID 和显式干净环境；复制 Node 到临时授权项目后验证授权项目读/写/删通过，带 `Authenticated Users: FullControl` 的兄弟 canary、合成私人目录及合成认证目录的读/写/删被拒，junction 越界被拒，子 Node 进程保持相同限制，Job Object 关闭会终止一个遗留子进程，敏感环境标记不继承。测试结束会恢复临时 canary ACL 并删除临时目录。

这不是独立账户验收：探针使用当前登录令牌派生测试令牌，并把当前 SID 置入合成限制 SID 集以便加载本机运行时；canary ACL 是合成 ACL。它不触碰或读取真实私人文件、真实 Codex 认证或真实项目 ACL，也没有验证命名管道 peer SID 或外网策略。必须在获批的阶段 B 用独立账户及合成 canary 重测。Windows 文档明确 restricted token 对对象进行普通 SID 和限制 SID 两次访问检查；本机探针也表明必须把实际执行工具所需的系统访问纳入 canary 验收，而不能只看路径白名单。

- 网络推理需要 Worker 出站访问。项目 ACL、restricted token 和 Job Object 都不能单独阻止进程通过网络外传；本方案不伪称已经具备网络沙箱。

## 为什么选此方案

- 单独标准账户把 Worker 与 Gateway 的用户配置和凭据分开。Restricted token 中和继承的宽组权限；受限 SID 与短期项目 ACL 收紧当前任务；Job Object 负责取消、超时和子进程清理；命名管道负责本机 peer 校验。
- Codex 自身的 workspace 沙箱曾能读写项目外 `%TEMP%` 合成文件，因此不把 Codex 设置或提示词作为 Windows 边界。
- Job Object 只管理进程生命周期，不替代文件 ACL。
- Task Scheduler 的 S4U 登录不提供网络凭据访问，不适用于需要 OpenAI 网络推理的 Worker。
- Windows Sandbox 在此 Windows Home 版本不可用，而且通用开发工具和用户授权项目挂载需要额外集成。

## 阶段 B 精确变更对象（需要单独批准）

在本机可用的 .NET Framework x64 C# 编译器上运行 `scripts/Build-TongWorkerSupervisor.ps1`，生成 `artifacts/native/TongWorkerSupervisor.exe`。源码位于 `native/TongWorkerSupervisor/`；`TongNativeWorkerSupervisor.mjs` 把现有 Broker 的 `inspectIsolation` / `launchWorker` 接到原生桥，`TongCodexWorkerMain.mjs` 使用原生令牌、Job 和 ACL 探针后才调用现有 Codex Worker。当前 `TongAgentTaskManager` 默认仍创建禁用执行的 Broker，没有把原生适配器接到 MCP 服务。

`tests/Test-TongNativeWorkerSupervisor.ps1` 只在 `%TEMP%` 下构造受保护的合成策略、Node 副本、模拟 Worker、项目与拒绝访问 canary。测试覆盖命名管道进程映像核对、HMAC 启动、真实 restricted token/Job、项目内外读写删除、junction、子进程、环境、取消、超时、ACL 精确恢复、异常恢复与冲突拒绝。合成模式使用当前账户，原生适配器明确拒绝将它当成生产隔离证明。独立账户 SID、服务 SID、真实目录有效访问、Worker 自有认证、Codex App Server 与公网网络边界均尚未验证。

以下批准清单中的 `NT SERVICE\TongWorkerSupervisor` SID 为 `S-1-5-80-2293798348-822329532-632115720-2296630101-786797740`；拟用 `NT SERVICE\TongGateway` SID 为 `S-1-5-80-530400873-148631718-326668357-2542268216-906724901`。本机 `sc showsid` 显示两者目前均未启用。当前 Gateway 主账户 `RUNE爱机\Rune` 的 SID 为 `S-1-5-21-2734333866-1484930161-1088177720-1001`，不能用它声称 Gateway 独占。建议后续另行批准将 Gateway 以 `NT SERVICE\TongGateway` 虚拟账户运行；原生管道核对其服务 SID 与实际主账户 SID，并拒绝与 Worker 主账户相同的配置。批准前须实际确认 Gateway 服务令牌 SID、现有 Gateway 启动配置与 OAuth 所需目录、每个真实项目的准确根路径与 DACL 备份位置、受保护安装后各文件的 SHA-256、Codex `--version` 精确输出；这些值不能从主用户 profile 复制或猜测。

1. **本地账户 / SAM：**新建 `TongCodexWorker`，仅属于 `BUILTIN\Users`；不属于 Administrators、Power Users 或 Remote Desktop Users。设置随机本地密码；密码只交给本机服务安装流程，不写入仓库、脚本输出、Gateway 环境或日志。
2. **本机用户权利：**为 `TongCodexWorker` 添加 `Log on as a service`（`SeServiceLogonRight`）和 `Adjust memory quotas for a process`（`SeIncreaseQuotaPrivilege`）；后者是服务用自己令牌的 restricted 版本调用 `CreateProcessAsUser` 所需的用户权利。restricted 版本的调用者不需要 `SeAssignPrimaryTokenPrivilege`。首次独立 `codex login --device-auth` 需要一次性本地交互登录；认证完成后注销交互会话。不要使用 S4U。
3. **SCM 服务与注册表服务键：**注册 `TongWorkerSupervisor`，`ImagePath` 固定为 `"C:\Program Files\Tong Desktop Control Worker\TongWorkerSupervisor.exe" --service "C:\Program Files\Tong Desktop Control Worker\worker-policy.json"`，服务账户为 `.\TongCodexWorker`，首次启动类型为 **Manual（demand start）**，服务 SID 类型为 `SERVICE_SID_TYPE_UNRESTRICTED`，不配置自动重启失败动作。所有真实验证通过后，再单独决定是否改为 Automatic。SCM 保存的服务登录秘密由 Windows 管理；服务配置只允许管理员更改，不授予 Gateway `SERVICE_CHANGE_CONFIG`。
4. **Worker 安装目录：**创建 `C:\Program Files\Tong Desktop Control Worker\`，所有者为 SYSTEM 或 Administrators。SYSTEM 和 Administrators 完全控制；Worker/Gateway 仅只读/执行。安装 `TongWorkerSupervisor.exe`、`node.exe`、`codex.exe`、`TongCodexWorkerMain.mjs`、`TongCodexWorker.mjs`、`TongWorkerStdio.mjs`、`TongWorkerProtocol.mjs`、`TongCodexAppServer.mjs` 和 `worker-policy.json`；逐个记录 SHA-256。策略记录 Codex `--version` 的精确输出，服务启动时核对版本、哈希与受保护执行目录；任务仍使用签名授权的项目根作为工作目录。不得引用主用户 profile 中的可执行文件、shim 或认证。
5. **Supervisor 状态与 Worker 认证目录：**创建 `C:\ProgramData\Tong\Worker\`，所有者为 SYSTEM 或 Administrators，仅 SYSTEM、Administrators 和 `NT SERVICE\TongWorkerSupervisor` 服务 SID 可访问；Worker 账户 SID、Gateway SID、Users、Authenticated Users 不得有访问 ACE。对状态文件的 OWNER RIGHTS 禁止修改 DACL。另建 Worker 自己的 `%USERPROFILE%\.codex` 和 `%LOCALAPPDATA%\Tong\Worker\Tasks\<taskId>`；Worker 账户只在这些目录按职责访问，主账户和其他普通用户无访问 ACE。使用 Worker 账户独立登录 Codex；禁止迁移主用户认证。
6. **工具安装目录 ACL：**策略中的 `toolDirectories` 精确列出 Git、Python 等工具目录；固定 Node EXE 位于受保护安装目录。按探针逐项审查工具及运行时依赖的真实 DACL，只给 Worker SID 必要的读取/执行，禁止写入；不修改 `C:\Windows` ACL，不给 Worker 宽泛的 D: 根目录权限。
7. **项目 ACL：**每个真实项目必须单独列明准确根路径及原 DACL 备份。安装前只给 `NT SERVICE\TongWorkerSupervisor` 服务 SID 在该根目录的 `ChangePermissions` 能力，以便运行时增删 ACE；restricted token 必须禁用该服务 SID。任务开始前，原生服务记录目录文件身份与原 DACL，并临时添加 Worker account SID 与该任务唯一 restricting SID 的 Modify ACE（目录和子项继承）。Job 中全部进程结束后按日志精确恢复；路径身份或 DACL 冲突时拒绝覆盖并保留日志供人工处理。服务异常中断后先恢复未完成日志，恢复失败就不开管道。不得授权 D:、工作区父目录或所有已注册项目。
8. **IPC 与进程对象：**命名管道 `\\.\pipe\TongWorkerSupervisor` 的 DACL 只允许 SYSTEM、管理员、专用 Gateway 服务 SID 和 Supervisor 服务 SID。连接后再次核对客户端 PID/token 中启用的 Gateway 服务 SID、Gateway 主账户 SID、固定桥接 EXE 路径与 SHA-256；桥接端核对服务 PID、Worker 主账户 SID、EXE 路径与 SHA-256。每个任务创建独立匿名 stdio pipe、restricted token 和带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的 Job Object；子进程禁止 breakaway。命令行固定，不传任务正文或密钥；HMAC key 仅走受保护管道与 Worker 私有启动环境。当前交互用户 SID 不能证明调用者是 Gateway，因此当前 P2.1 Gateway 不接通此 IPC。
9. **系统网络和环境：**不改防火墙、系统 PATH、全局环境变量或代理。Worker 使用固定环境白名单，保留 Codex 推理所需出站网络；允许网络意味着仍有外传风险。若要限制目标域名，需要单独设计并批准代理/防火墙策略。
10. **Gateway 身份与系统服务状态：**当前 Gateway/DevSpace/ngrok 和 MCP OAuth 配置不变。若要将来接通 Worker，必须另行批准把 Gateway 改为 `NT SERVICE\TongGateway` 虚拟账户运行的服务，单独审查 `D:\tong-desktop-control` 的代码、`config\tong.config.json`、`runtime\`、`logs\` 与 OAuth/DevSpace 依赖目录所需 ACL，记录旧启动配置和回滚路径；不能复用交互用户 SID 冒充 Gateway 独占身份。真实 Codex 执行只有在独立账户、Gateway 服务令牌、文件/目录 ACL、IPC peer、Job、凭据隔离及回滚验收全部通过后，才可单独批准接通 Worker launcher；配置缺失仍返回 disabled。

## 执行顺序与回滚

批准后先安装账户与 **Manual** 服务，但保持 MCP launcher disabled；Gateway 专用服务 SID 的身份切换另行批准。为每个计划测试的真实项目在本地受保护目录保存 DACL 备份；不要把 ACL dump 提交 GitHub。先运行独立 Worker canary：授权项目读写、兄弟项目读/写/删拒绝、主用户 profile canary 拒绝、Tong auth canary 拒绝、junction/symlink 拒绝、子进程同权限、环境无主用户变量、命名管道只接受 Gateway 服务 SID、Job handle close 清理所有后代；记录网络外传限制仍未解决。复核后再请求是否连接 launcher 与是否设置 Automatic。

回滚顺序：先断开 MCP launcher，停止 `TongWorkerSupervisor` 并关闭所有 Job；恢复所有项目的 ACL 备份并逐项比较，包括预授权的 Supervisor 服务 SID `ChangePermissions` ACE；保留并处理任何冲突日志；移除服务注册（SCM `TongWorkerSupervisor` / 对应 `HKLM\SYSTEM\CurrentControlSet\Services\TongWorkerSupervisor` 键）；删除 `SeServiceLogonRight` 和 `SeIncreaseQuotaPrivilege` 中的 Worker SID；若曾单独批准 Gateway 服务 SID 身份切换，按原配置快照恢复 Gateway；在 Worker 身份下注销 Codex 并删除其认证目录；确认无任务后删除 Worker profile、`C:\ProgramData\Tong\Worker\` 和 `C:\Program Files\Tong Desktop Control Worker\`；最后删除本地账户 `TongCodexWorker`。若 SCM 标记服务待删除，重启后复核服务键与账户。当前 P2.1 服务未被本次 B0 改动。

脚本 `scripts/Plan-TongWorkerIsolation.ps1` 与 `scripts/Plan-TongWorkerIsolationRollback.ps1` 只打印上述计划。它们没有 apply 开关实现；传入 `-Apply` 会直接报错。
