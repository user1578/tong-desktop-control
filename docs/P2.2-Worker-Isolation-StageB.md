# P2.2 Windows Worker 隔离：阶段 A 结果与阶段 B 批准清单

## 状态

阶段 A 已完成代码、模拟测试和临时 canary 探针。真实 Worker 启动器仍未配置；MCP 中真实 Codex 执行保持关闭。阶段 B 的系统对象变更未执行。

推荐方案：单独的标准本地账户 `TongCodexWorker` 承载一个很小的 Windows 服务 `TongWorkerSupervisor`。Gateway 通过仅允许 Gateway SID 和 Worker 服务 SID 的本机命名管道提交已授权任务。Supervisor 对每个任务创建低权限 restricted token 和独立 Job Object；Codex、Git、Node、Python 及其全部子进程都在该 token 和 Job 中运行。每次只向一个已授权项目和任务临时授予 ACL，任务结束或取消后撤销。

`Authenticated Users` 在 Worker 令牌的普通访问检查中设置为 deny-only，用来中和当前 D: 目录树继承的 `Authenticated Users: Modify`。受限 SID 的第二次访问检查用于确认 Worker 账户、任务 SID 或已检查的只读系统依赖确实获准。Supervisor 是可信计算基的一部分，只接受固定任务协议，不提供 Shell、任意命令或任意路径接口。

## 阶段 A 完成项

- `TongWorkerBroker` 在执行前重新验证 `agent.execute`、已注册项目根路径和隔离状态。缺少已验证的隔离检查或启动器时直接拒绝；没有回退到 Gateway 身份的分支。
- Worker 消息使用 v1 精确字段协议、每次任务随机 32 字节 HMAC 密钥、最大帧大小和任务 ID 绑定。密钥由启动器通过私有启动通道提供；任务正文和授权根路径只通过私有 IPC 发送。
- Worker 只接收注册项目根目录，不接受客户端 executable、命令行或环境变量。启动器需要提供完整的进程/Job 会话，否则已创建的 Job 会先终止并关闭。
- Worker 验证实际隔离快照、固定绝对 Codex 可执行文件及 SHA-256、隔离环境和日志脱敏。没有身份探针时安全失败。
- stdio IPC 覆盖有效任务、伪造签名拒绝、任务取消和错误回传；任务管理器覆盖权限撤销、持久状态、取消隔离和错误恢复。
- `tests/Test-TongWorkerCanaries.ps1` 在 `%TEMP%` 下创建隔离 canary。使用当前进程派生的 restricted token、临时限制 SID 和显式干净环境；复制 Node 到临时授权项目后验证授权项目读/写/删通过，带 `Authenticated Users: FullControl` 的兄弟 canary、合成私人目录及合成认证目录的读/写/删被拒，junction 越界被拒，子 Node 进程保持相同限制，Job Object 关闭会终止一个遗留子进程，敏感环境标记不继承。测试结束会恢复临时 canary ACL 并删除临时目录。

这不是独立账户验收：探针使用当前登录令牌派生测试令牌，并把当前 SID 置入合成限制 SID 集以便加载本机运行时；canary ACL 是合成 ACL。它不触碰或读取真实私人文件、真实 Codex 认证或真实项目 ACL，也没有验证命名管道 peer SID 或外网策略。必须在获批的阶段 B 用独立账户及合成 canary 重测。Windows 文档明确 restricted token 对对象进行普通 SID 和限制 SID 两次访问检查；本机探针也表明必须把实际执行工具所需的系统访问纳入 canary 验收，而不能只看路径白名单。

## 调查得到的本机信息

- Windows 11 Home，x64，build 26200。Windows Sandbox 在 Home 版本不可用。
- Codex CLI `0.155.0-alpha.16.3`；当前可执行文件位于 `C:\Users\Rune\AppData\Local\OpenAI\Codex\bin\80f78947ad880e6e\codex.exe`，npm shim 位于 `%APPDATA%\npm\codex.ps1`。App Server 以固定 executable 启动，通过 stdio JSON-RPC 通信；当前适配器使用 `codex app-server --listen stdio://`，shell 关闭。App Server 仍为实验接口；Stage B 必须在 Worker 身份下重验当前版本。
- Git `2.53.0.windows.3`：`C:\Program Files\Git\cmd\git.exe`；Python `3.11.9`：`C:\Program Files\Python311\python.exe`；Node `v24.15.0`：`D:\node\node.exe`。工具通过只读/执行 ACE 提供，不继承 Gateway 环境变量；实际 ACL 在阶段 B 前仍需逐项检查。
- 当前登录账户为 `RUNE爱机\Rune`，中完整性令牌；Administrators SID 在当前令牌中为 deny-only。Gateway、DevSpace 和 ngrok 仍由该交互账户运行。Gateway 7676 和 DevSpace 7677 只监听 loopback；阶段 A 未重启或切换这些服务。
- `D:\tong-desktop-control` 继承 `Authenticated Users: Modify`；`D:\node` 的现有 ACL 允许 `Authenticated Users` 读取/执行。这是不能直接让 Worker 使用主账户或只依赖项目路径检查的原因。阶段 A 没有改变这些 ACL。
- Codex 的 CLI 认证属于各自 `CODEX_HOME`/Windows 身份。默认文件存储可能包含可用凭据；Worker 必须在自己的账户下单独登录，禁止复制主账户的 token、Cookie 或 `.codex` 内容。
- 网络推理需要 Worker 出站访问。项目 ACL、restricted token 和 Job Object 都不能单独阻止进程通过网络外传；本方案不伪称已经具备网络沙箱。

## 为什么选此方案

- 单独标准账户把 Worker 与 Gateway 的用户配置和凭据分开。Restricted token 中和继承的宽组权限；受限 SID 与短期项目 ACL 收紧当前任务；Job Object 负责取消、超时和子进程清理；命名管道负责本机 peer 校验。
- Codex 自身的 workspace 沙箱曾能读写项目外 `%TEMP%` 合成文件，因此不把 Codex 设置或提示词作为 Windows 边界。
- Job Object 只管理进程生命周期，不替代文件 ACL。
- Task Scheduler 的 S4U 登录不提供网络凭据访问，不适用于需要 OpenAI 网络推理的 Worker。
- Windows Sandbox 在此 Windows Home 版本不可用，而且通用开发工具和用户授权项目挂载需要额外集成。

## 阶段 B 精确变更对象（需要单独批准）

1. **本地账户 / SAM：**新建 `TongCodexWorker`，仅属于 `BUILTIN\Users`；不属于 Administrators、Power Users 或 Remote Desktop Users。设置随机本地密码；密码只交给本机服务安装流程，不写入仓库、脚本输出、Gateway 环境或日志。
2. **本机用户权利：**为 `TongCodexWorker` 添加 `Log on as a service`（`SeServiceLogonRight`）和 `Adjust memory quotas for a process`（`SeIncreaseQuotaPrivilege`）；后者是服务用自己令牌的 restricted 版本调用 `CreateProcessAsUser` 所需的用户权利。restricted 版本的调用者不需要 `SeAssignPrimaryTokenPrivilege`。首次独立 `codex login --device-auth` 需要一次性本地交互登录；认证完成后注销交互会话。不要使用 S4U。
3. **SCM 服务与注册表服务键：**注册 `TongWorkerSupervisor`，映像固定为 `C:\Program Files\Tong Desktop Control Worker\TongWorkerSupervisor.exe`，服务账户为 `.\TongCodexWorker`，启动类型为 Automatic (Delayed Start)，服务 SID 类型为 `SERVICE_SID_TYPE_UNRESTRICTED`，不配置自动重启失败动作。SCM 保存的服务登录秘密由 Windows 管理；服务配置只允许管理员更改，不授予 Gateway `SERVICE_CHANGE_CONFIG`。
4. **Worker 安装目录：**创建 `C:\Program Files\Tong Desktop Control Worker\`。`SYSTEM` 和 Administrators 完全控制；Worker 账户只读/执行；Worker 进程不可修改自身可执行文件、Codex binary 或依赖。把经验证的 Codex 版本安装/复制到该受保护目录，校验 SHA-256 和 App Server 启动，不依赖主用户 profile 中的 shim。
5. **Worker 数据与认证目录：**创建 `C:\ProgramData\Tong\Worker\`（Supervisor 状态/受保护日志）及 Worker 自己的 `%USERPROFILE%\.codex` 和 `%LOCALAPPDATA%\Tong\Worker\Tasks\<taskId>`。Worker 和 SYSTEM 按职责访问；主账户、其他普通用户无访问 ACE。使用 Worker 账户独立登录 Codex；认证文件/Windows keyring 只属于 Worker。禁止迁移主用户认证。
6. **工具安装目录 ACL：**按探针逐项审查 Git、Node、Python 及其运行时依赖的真实 DACL。只给 Worker SID 必要的读取/执行，禁止写入；不修改 `C:\Windows` ACL，不给 Worker 宽泛的 D: 根目录权限。
7. **项目 ACL：**每个运行中的任务只对其 `agent.execute` 已授权的准确项目根目录保存原 DACL 备份，并临时添加 Worker account SID 与该任务唯一 restricting SID 的 Modify ACE（目录和子项继承）。任务 Job 关闭后移除这两个 ACE，校验 ACL 与备份相符。不得对 D:、工作区父目录或所有已注册项目使用递归授权。真实目标目录必须在批准时逐一列明。
8. **IPC 与进程对象：**命名管道 `\\.\pipe\TongWorkerSupervisor` 的 DACL 只允许 SYSTEM、管理员、Gateway SID 和 Worker 服务 SID；连接后再次用客户端 PID/token 校验 Gateway SID。每个任务创建独立匿名 stdio pipe、restricted token 和带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的 Job Object；子进程禁止 breakaway。命令行固定，不传任务正文或密钥；HMAC key 仅走私有 Worker 启动通道。
9. **系统网络和环境：**不改防火墙、系统 PATH、全局环境变量或代理。Worker 使用固定环境白名单，保留 Codex 推理所需出站网络；允许网络意味着仍有外传风险。若要限制目标域名，需要单独设计并批准代理/防火墙策略。
10. **系统服务状态：**原 DevSpace、Gateway、ngrok 和 MCP OAuth 配置不变。真实 Codex 执行只有在全部 Stage B canary、IPC peer、Job Object 和回滚验收通过后，才可通过单独审批接通 Worker launcher；配置缺失仍必须返回 disabled。

## 执行顺序与回滚

批准后先安装账户与服务，但保持 MCP launcher disabled。为每个计划测试的真实项目在本地受保护目录保存 DACL 备份；不要把 ACL dump 提交 GitHub。先运行独立 Worker canary：授权项目读写、兄弟项目读/写/删拒绝、主用户 profile canary 拒绝、Tong auth canary 拒绝、junction/symlink 拒绝、子进程同权限、环境无主用户变量、命名管道只接受 Gateway SID、Job handle close 清理所有后代；记录网络外传限制仍未解决。复核后再请求是否连接 launcher。

回滚顺序：停止 `TongWorkerSupervisor` 并关闭所有 Job；恢复所有项目的 ACL 备份并逐项比较；移除服务注册（SCM `TongWorkerSupervisor` / 对应 `HKLM\SYSTEM\CurrentControlSet\Services\TongWorkerSupervisor` 键）；删除 `SeServiceLogonRight` 和 `SeIncreaseQuotaPrivilege` 中的 Worker SID；在 Worker 身份下注销 Codex 并删除其认证目录；确认无任务后删除 Worker profile、`C:\ProgramData\Tong\Worker\` 和 `C:\Program Files\Tong Desktop Control Worker\`；最后删除本地账户 `TongCodexWorker`。若 SCM 标记服务待删除，重启后复核服务键与账户。Gateway 的 P2.1 服务和分支不回滚/不切换。

脚本 `scripts/Plan-TongWorkerIsolation.ps1` 与 `scripts/Plan-TongWorkerIsolationRollback.ps1` 只打印上述计划。它们没有 apply 开关实现；传入 `-Apply` 会直接报错。
