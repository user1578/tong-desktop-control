开发基线：`58786f6`；开发分支：`codex/p24-agentdock-client`。本阶段在独立 worktree 开发，未部署或覆盖 `D:\tong-desktop-control` 的现有运行配置。AgentDock v1.0.1 上游源码未修改。

## 模块与工具

| 模块 | 职责 |
| --- | --- |
| `scripts/TongAgentDockClient.mjs` | 复用 MCP SDK 1.32.1 的 Client / StreamableHTTPClientTransport；初始化、Bearer、发现和 Schema 验证、调用、限额、关闭、安全错误。 |
| `scripts/TongAgentDockPaths.mjs` | 校验绝对/相对项目路径；拒绝 `..`、UNC/设备名、ADS、链接/junction、硬链接、Windows 原始 ReparsePoint 属性；检查后代和执行后身份变化。PowerShell 仅运行固定元数据程序，路径以 UTF-8 JSON stdin 传入。 |
| `scripts/TongAgentDockTools.mjs` | 独立合成项目授权、固定读路由、参数验证、结果过滤、审计。 |
| 现有注册/Gateway/补丁脚本 | 增加下列三个固定读工具；保持 Codex 和原工具路线。SDK 原有传递依赖升为相同版本的直接依赖。 |

| Tong 工具 | AgentDock 工具 | 本地许可与限额 |
| --- | --- | --- |
| `tong_agentdock_list_dir` | `list_dir` | 项目登记的 `read/write` + 独立 `list_dir` grant；目录深度 1–3，最多 200 项。 |
| `tong_agentdock_read_file` | `read_file` | 同上且独立 `read_file` grant；单文件，最多 64 KiB，可指定行范围。 |
| `tong_agentdock_search_text` | `search_text` | 同上且独立 `search_text` grant；目录内固定文本搜索，查询最多 512 字符、最多 100 结果。 |

没有任意 `toolName + arguments` 公共转发入口。新客户端仅允许这三个 backend 工具；没有加入 `file_edit`、Shell、会话、动态 MCP、Skill、ACP。原 PoC 的命令能力仍保留在 PoC 测试文件中。

## 本地配置与授权

默认关闭。仅在隔离开发进程内设置：

```powershell
$env:TONG_AGENTDOCK_ENABLED = '1'
$env:TONG_AGENTDOCK_URL = 'http://127.0.0.1:18765/mcp'
$env:TONG_AGENTDOCK_POLICY_PATH = '<独立、受保护的本地授权文件>'
# TONG_AGENTDOCK_TOKEN 由本机环境提供；不要在命令、源码或报告中填写实际值。
```

URL 只接受数字形式的 IPv4 `127/8` 或 IPv6 `::1`，拒绝用户信息、query、fragment 和 HTTP 重定向；不解析任意 DNS 主机。默认地址如上。认证 Token 不与 Tong OAuth 共享，也不写入 Git。SDK 管理协议和连接资源；默认请求 32 KiB、响应 256 KiB、单请求 5 秒，配置限额有上限。断线/超时返回明确错误、关闭旧连接；后续调用可重新初始化，无自动命令或本地 Shell fallback。

授权文件默认 `runtime/agentdock-access.json`（未提交且不存在时拒绝所有调用）。本机可信操作者显式登记合成项目后，另配置：

```json
{
  "schemaVersion": 1,
  "projects": [{
    "projectId": "synthetic-project",
    "root": "D:\\agentdock-poc-20261010\\example-synthetic-project",
    "scope": "synthetic",
    "tools": ["list_dir", "read_file", "search_text"]
  }]
}
```

`root` 必须与 Tong 项目登记记录一致，项目必须 enabled、available，登记许可为 read 或 write。`agent.execute` 不参与此判断；原项目读能力和 Codex 执行授权不会自动产生 AgentDock grant。调用完成后再次核对授权和项目根目录；处理中撤销 grant 或更换 root 会阻止返回。`scope=synthetic` 是本机操作者的明确声明，不能自动证明项目内容无敏感信息。第一阶段只允许操作者已确认的合成项目。

授权文件应置于本机受保护目录，例如已获批准的 PoC `isolated/state`，避免其他本地账户篡改。模块不自行扩大 ACL 范围或启用生产功能。

## 路径、结果和审计

调用顺序为项目定位、独立许可、路径检查、参数校验、MCP、后检查、结果过滤、审计。目标路径不能被证实时拒绝；列表和搜索结果只接受预先检查过的 manifest 路径，返回项目相对路径及固定字段。目录搜索预先检查完整树，超过 2000 项或 20 层、含隐藏/凭据类路径时拒绝；这是第一阶段的保守限制。列表不返回保护项。禁止向客户端透传原始后端错误正文或任意结果字段。

`runtime/agentdock-audit.jsonl` 记录生成的请求 UUID、项目 ID、固定工具名、项目相对目标（仅已验证时）、耗时、allowed/denied/failed 和错误类型；不保存 Token、搜索正文或文件内容。审计写入失败时调用失败。日志与凭据均位于忽略路径。Token 检查作用于实际字符串内容，避免 JSON 转义造成泄漏；工具响应或描述含当前 Token 会被拒绝。

AgentDock 自身仍拥有进程账户的权限。路径检查和调用后验证降低链接替换/授权变更风险，但跨进程检查与读取不能构成原子的 OS 沙箱；恶意本地进程的精密并发替换仍是边界。只在受信任的合成项目里验收，不能把 `workdir`、manifest 或 grant 当作任意 Shell 的安全隔离。

## 已知兼容性与 P2.4.4

AgentDock v1.0.1 的 Windows 绝对路径结构化补丁有已知错误；P2.4.4 应使用相对补丁和明确 workdir，并先 dry run。部分后端错误无稳定 code，目前对外归一为 `TOOL_FAILED`。搜索源码把 query 放入 rg 参数时没有 `--`，本层拒绝以 `-` 开头的查询；搜索仅接受目录，避免上游 rg 的文件 workdir 问题。WSL 警告 stderr 有编码问题，本阶段不开放 WSL 工具参数。OAuth、stdio、动态 MCP、ACP 和公网 ChatGPT 端到端未验收。

P2.4.4 应先审查本阶段授权/故障证据，再添加独立写许可、操作级预览确认、幂等/结果未知处理；Shell 必须另有受限 OS 执行身份和逐命令批准，不能复用项目读取 grant。最后在单独获准的开发连接上做 ChatGPT → Tong → AgentDock 端到端验收，再决定部署。当前不合并 main、不 push、不生产部署。
