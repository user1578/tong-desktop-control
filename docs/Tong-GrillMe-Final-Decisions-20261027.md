# Tong Desktop Control — 22项需求定稿与架构决定

状态：用户确认的22项需求定稿；本文件作为长期项目需求依据纳入开发仓库。它不代表功能已经开发或生产部署；实际Git提交和远端同步以本次提交回执为准。

## 产品定位

ChatGPT作为主Agent负责理解目标、任务拆分、选择执行者、监督、复核及统一最终报告。Tong是单一Windows MCP工具/多Agent调度入口，默认由ChatGPT通过Tong直接操作，用户指定Codex/DSH/Claude等才路由给指定Provider。用户明确要求自主分配时，ChatGPT可选择单个或多个Agent。不要把Agent一轮回复当作整个业务目标完成。

## Grill-Me选择汇总

1. 主要个人使用，GitHub易于公开安装，以便换电脑/换账号。
2. 第一版PowerShell命令或BAT引导安装，不急于exe安装器。
3. 优先Windows 11，WSL/Ubuntu/Linux后续再评估。
4. 安装程序检查并在授权下安装缺失依赖。
5. 保留已验证核心，但允许有边界地简化、重构冗余或不稳定模块。
6/18. 18B为最终选择：**按需启动**，不要求登录或开机自动运行，托盘图标不是前置目标；先实现摘要与任务完成反馈。
7. 自动进行有限恢复，失败停止并通知；不能无限重启。
8. 默认ChatGPT直接操作；用户指定Agent或要求自动分配时按真实能力调度。
9. Codex Desktop优先、DeepSeek Harness常用，逐渐支持Claude Code、Zcode/Zode、Work Buddy以及新安装Agent。
10/20. 希望Codex运行中在Desktop可见；在上游列表同步仍不稳定时，优先保证Tong任务状态可查询、原生Session可恢复，不让UI刷新阻塞执行。
11/19. 19A：长任务在本机Tong中继续执行；**任务完全完成、额度不足、必须用户操作或不可恢复故障时通知**。用户不想不断主动询问进度。
12. ChatGPT对话内查询进度和可选Tong独立看板并存；不承诺已结束ChatGPT消息自动改写。
13. 期望Windows文件/程序/浏览器/桌面操作；优先核查复用已有AgentDock，不重造。
14. 普通开发与确认无用的可重建缓存自主处理，真正高影响系统/生产/重要数据变更单独确认。
15. ChatGPT直接查修或委派Codex均可；最重要的是新对话不需要用户重新粘贴大段背景。
16/21. 21A：自动检查/下载、空闲安全窗口更新普通补丁，详细记录；升级失败健康检查后自动回退；重大/权限/兼容性变化另确认。
17. 首要反目标：占用持续膨胀、反复授权、更新后Tong无法启动。
22. 确认可重建且未引用的缓存/旧测试可精确删除，个人聊天和下载资料需先列候选清单等用户允许清理规则。

## 架构设计：渐进式简化

保留Gateway/认证及项目授权、现有文件工具和AgentDock可复用能力、Codex App Server原生Session桥、Goal Supervisor持久状态/审查及Git版本。审计LoginHost、Runner、Supervisor、Guardian是否有重复启动/恢复权力：**一个权威状态持有者、一条有权限门禁的生命周期入口**。先小范围实验和有界验收，不能直接移除保护模块或部署未验收架构。

Provider定义discover/health/capabilities/authorize/start/resume/status/events/cancel/result/nativeLink；各Agent的CLI和Desktop原生可见性必须区分，不能虚构Session。统一公共Goal MCP而非每增加一个Agent就扩一套公开工具。

## 首要交付：摘要、长任务、额度不足恢复

完整Goal包含goalId/projectId/provider/nativeSessionId/各turn/持久步骤、预算、受管授权及实测验收证据。内部Turn结束不得向用户发整体完成报告；ChatGPT在同一Goal下继续审查修复。最终**一次性摘要**包含结果、已验收/未完成、修改/测试/提交、原生会话、下一步。额度/速率限制/模型容量不够时持久暂停并通过Windows通知或本地看板提示，保留原Session与未完成步骤；不在未知恢复时间频繁探测或重复高影响操作。有明确可重试信号且预算许可时有限重试，仍不能恢复则待用户介入或以后续接。

按需启动不等于关闭聊天就停止：Tong启动后持有尚在执行/暂停的本地Goal，ChatGPT页面关闭后任务仍可进行。电脑关闭/本地服务停止时只保留可恢复记录，下一次启动核对恢复条件。任务进度在当前聊天和独立可查询看板显示真实状态与时间；普通MCP不保证能主动向已经结束的ChatGPT聊天发送新消息。初期可靠通知优先Windows弹窗和持久本地状态，不为此先做托盘App。

## Windows 11一键安装、自动小补丁及回退

从GitHub正式release运行setup PowerShell/BAT，自动检测Node/PowerShell/Git/必要依赖并给出可信安装选项，配置自由安装根、工作/配置/日志/凭据分别存储，不依赖D:\\Tong或D:\\node硬编码。安装后受管授权项目、重新登录连接器/Agent。用户换账号/换电脑选**全新配置**，不迁移旧凭据/运行状态/会话。提供setup/start/status/stop/doctor/logs/update/rollback/uninstall的清晰命令入口（规划中，并非当前存在）。

自动补丁必须检查可信版本、清单和哈希、空间预算，活动任务/Writer存在时推迟切换；安装后完整健康检查，不通过则回退到最近经过验证的已知正常版本，记录旧新版本、时间、校验、结果和失败原因。破坏兼容/授权/系统配置的重大变化单独批准。禁止每次回归留下数百MB完整副本；保留必要的有限回退资产。

## PC维护与清理

Tong支持只读扫描C/D磁盘、文件逻辑/实际可回收量、RAM/CPU/GPU/进程/服务/网络/启动项，提供具体安全的清理建议。用户授权或白名单范围内可精准删除无消费者的缓存/重复发布副本，不对不确定的聊天记录、下载材料、真实生产pin/DB/身份数据进行猜测式清理。用户会另行补充允许自动清理清单。删除结果要有路径、大小、前后验证，不再整目录备份可重建垃圾。

## 跨新对话接手与维护

GitHub是代码、设计决策、非敏感版本和任务进度的事实源；本地Tong是运行真相的事实源。新聊天说“帮我检查/修复Tong”，应先定位`user1578/tong-desktop-control`，阅读AGENTS.md、本总任务书、项目现况/交接、最新发布/故障记录、专项计划，再从真实Git status与本机进程/pin/日志判断当前故障。若本地Tong掉线，应先查GitHub与获授权的恢复入口，不能宣称已用本机工具修好。

**不能保证**完全新的ChatGPT账号自动获得旧账号记忆、连接器或Windows授权；它可依简短仓库指针迅速重新理解项目，登录/授权需在新账号重新建立。不要要求用户每次贴多页交接。每次开发只更新少数权威入口+必要证据/提交，不复制几十份报告。

## 验收里程碑及实施次序

- R0：审计现有源码、生产版本绑定、职责层次、硬编码/补丁和单独生命周期入口，输出精确保留/替换清单。
- R1：摘要、Goal多轮业务验收、额度不足持久暂停/通知/同Session续作，真实小任务验收（优先）。
- R2：按需启动、有限恢复、清晰doctor/错误原因，浏览器关闭后本机运行/下次启动恢复验收。
- R3：Win11全新配置一键安装，非原机路径安装实测。
- R4：版本化小补丁更新、日志与回滚，升级失败注入测试。
- R5：真实任务进度与独立看板、Codex Desktop无重启可见性持续研究。
- R6：统一Provider接口，DSH/Claude实际受控任务再扩其他Agent。
- R7：PC资源观测、精准清理、实测容量变化及长期归档。

所有开发只在授权codex分支提交推送，不改main。未经正式许可不更新正式生产、ACL、认证、Windows任务或重置预算。
