# 公开范围、脱敏与证据限制

## 来源与处理

清单覆盖维护根内全部61个文件及16个明确列出的关联文件，共77个。原始路径、字节大小、原始 SHA256、原始修改时间、公开路径和未公开原因逐项保存在 `FILE-INVENTORY.json` / CSV。

维护根内58个文件提供脱敏副本；3个仅列元数据：外部 `TongLoginHost.exe`，以及两个0字节 gate/evidence 文件。编译二进制没有可靠的逐字段脱敏边界；空文件没有可公开的诊断内容，其 SHA256、FileKey 关系和用途已由元数据覆盖。未上传这些文件不代表它们丢失或被删除。

未打开或复制真实业务数据库、OAuth/用户完整配置、DPAPI envelope、私钥、恢复密钥或挑战凭据。`files.pre-handoff.json` 本来就是加密文件的 size/SHA 元数据；公开版进一步用编号代替私有权限存储文件名，没有读取其中任何密文内容。

## 脱敏规则

- 授权 grant/recoveryGrant 标识及其他凭据字段替换为占位符；跨文件文本出现的相同私有标识一并遮蔽。
- 个人 Windows SID、用户目录、用户名和机器名替换为占位符；保留系统/管理员组的通用 SID 及 LocalSystem 服务身份。
- 私有公网连接地址替换为占位符；保留本机端口和进程/Job 元数据。
- 历史 reconciliation 中嵌入的 runtimeRecord/guardianRecord 先按 JSON 解析，再递归脱敏，避免只遮蔽外层字段。
- JSONL 每条原始记录对应一条脱敏记录，保留窗口内日志行顺序；筛选的关联历史日志明确记录原始/公开条数。
- 原始 Task XML 以 `.xml.txt` 公开，个人身份以文本占位符代替。辅助脚本和源码以 `.txt` 公开，仅供复审，不作为恢复入口。

runId、UTC时间、错误码、PID、startTicks、Job 字段、正常的源代码摘要和清理结果保留。不要把公开的脱敏控制记录重新用作生产控制文件。

## 筛选与缺失

- `guardian.jsonl` 原始7876条，公开旧事故的6条非 heartbeat 关键事件；本次新 runId 匹配0条。完整原始日志留在本机。
- `supervisor.jsonl` 24条均提供脱敏版本；本次新 runId 匹配0条。
- 登录恢复授权审计104条，仅公开本窗口2条；grant 标识遮蔽。`denied` 的真实代码含义见 `CLEANUP-ANALYSIS.md`。
- Windows 事件查询仅查询既有日志的窄时间窗，不启用日志、不导出完整 evtx。TaskScheduler Operational 原已关闭、Sysmon 通道不可用；三个 PowerShell 通道在查询窗内没有返回事件。该观察发生在资料整理时，不能证明事故时进程没有创建，也不能断言日志未轮转。
- 没有保存 Launcher PID/创建时间/退出码、stdout/原始 stderr、每轮 guardianComplete 返回原因或完整内存异常。报告没有补造这些内容。
- 原操作通过交互工具逐步执行；此维护目录没有完整逐命令转录。控制者 JSON 中的断言应结合产品源码、产品日志和文件摘要评估，不能冒充独立内核跟踪。

## 摘要与验证

`originalSha256` 对应保留在本机的原始字节。公开副本经筛选、脱敏或换行规范化后，SHA256 通常不同；`publicFiles` 给出副本自身的字节摘要。嵌入记录脱敏后，历史记录里的原始 runtimeSha256/guardianSha256 不再是脱敏嵌入文本的摘要，这是预期结果。

生产源码的 CRLF 字节先与 pin 核对，再和精确 Git blob 按 LF 比较；公开代码选取该 Git blob，必要时遮蔽身份/地址，不修改产品。原版源码字段中的 `token`、`ciphertext` 等名称不是本次收集到的凭据值。

提交前检查范围包括：所有生成文件、已发现的私有授权标识、个人身份模式、私钥/常见令牌/JWT模式、递归 JSON 敏感字段、原始文件 SHA 再核对、逐文件 Git 暂存范围。自动模式检查不能构成绝对无敏感信息的数学证明，因此同时使用了限定来源、结构化脱敏和内容复核；没有先提交私密原件再删除。
