> **2026-10-29 用户最新明确要求，本文件优先于历史版本中“每次都要审批、先全盘扫描”的设计假设。**
> **状态：研发任务书，不代表新功能已部署。** 不改变现有操作系统权限、MCP边界或既有清理许可。普通清理应消除重复确认，但不允许通过Shell、提权或绕过受管工具实现。

## 一、最终使用方式：说了就做，不再走重复审批

### 1. 用户说“清理空间 / 清理缓存 / 把临时文件清掉”

这句话就是**执行请求**，不是让Tong只生成报告。ChatGPT直接调用Tong，按下文A类白名单识别并清理当前用户权限内、已有受管工具允许的安全临时文件；无需再次问“是否确定”、逐文件确认或让用户复制PowerShell。对已经可靠证实为可重建、无当前使用依赖的B类缓存，也可以直接执行；不能证明安全的跳过并报告，不因一项不确定阻塞其他项。

**不能把这句话当成“可以递归清空C/D盘”或“改权限、关软件、删账户数据”的授权。** 现有正式MCP的实际清理许可仅限`D:\Tong\state`及其既定类别；新增C/D缓存操作应优先复用当前Windows用户可执行的**合法、有限范围的受管清理能力**，不另造每次审批的门槛。若底层原有安全门禁确实不允许该范围，就完成其它已获准项，并一次性说明缺失的权限范围；不得假装已清、不得绕过门禁。只有首次建立确有必要的新系统级权限时，才使用现有正规本机配置流程，建好后不逐次询问。

### 2. 用户明确说“删除 D:\xx\yy”或列出一组具体对象

对**非硬保护对象**，这就是精确删除指令：Tong按给定路径核对实际对象/引用边界，能够安全直接执行就执行；不要再发确认问题，不要先扫描整个磁盘，不要改成只读计划书。路径不存在如实报告，无法访问/正在使用则跳过说明。用户指定的路径不意味着同目录其他文件也获准删除。

对硬保护对象，不能用通用清理接口误删；要指出实际受保护项及原因，不能静默删除。不能为了满足“删整个目录”而连带删除其中受保护的文件。

### 3. 三个目标优先级

**第一：真实释放空间。第二：保护用户数据和工作环境。第三：减少等待和多余操作。** 不追求删除文件夹数量，不重复建设复杂审批/权限框架；不能只扫半天、清十几MB就将数GB目标报成完成。无需为了每次清理新建完整备份副本或重跑全项目测试。

## 二、绝对保护范围——默认自动清理和指定整目录均不得波及

以下为**硬保护规则**，在扫描分类、Plan、Execute、递归下降和归档候选删除时都生效。对命中这些规则的文件**原位保留**；目录内含硬保护文件时，不可递归删除整个父目录，应只处理其中明确安全的子目录。

1. **账户与身份信息**：Windows用户账户资料、浏览器登录状态与Profile数据、Cookies、会话/Local Storage、密码库、OAuth/Refresh Token、API Key、SSH私钥、证书、DPAPI、认证/授权策略、账号备份、云同步元数据。不要读取这些内容来“判定是不是缓存”，不重置登录，不清除账号，不修改ACL/组策略。
2. **Agent与AI工作配置**：任何大小写的`AGENTS.md`、`agent.md`、`CLAUDE.md`，其它用户编写的Agent指令/规则MD、项目文档与个人`.md`，以及Agent配置目录、`.codex`、`.claude`、MCP配置、skills、工作流、会话历史、原生Codex Desktop会话和已连接工具配置。即使文件落在`temp`、旧候选、重复依赖父目录里也必须保留。**不能仅凭`.md`后缀就把用户文档当垃圾。**唯一例外是经锁文件/完整来源证明、位于可重建第三方依赖副本内部的普通包说明（例如`node_modules`里的第三方`README.md`），可随相应已获准的重复依赖一起清理；`AGENTS.md`/`agent.md`/`CLAUDE.md`本身仍强制保留，不因第三方目录例外而删除。
3. **用户独有数据与开发状态**：Documents/Desktop/Downloads/Pictures/Videos、个人项目源码、Git仓库`.git`与未提交文件、笔记、配置、脚本、导出报表、真实数据库/备份、虚拟环境、模型权重、唯一归档、工作区任务状态；不会因为“大”“旧”或文件夹名叫temp就删除。
4. **Tong生产与事故材料**：`D:\Tong\app`、`D:\Tong\runtime`、生产pin、当前使用的release/staged、回退快照、审计、许可、监控/事故证据、Task配置、Gateway/ngrok配置及现有Agent会话。不得顺带清理`0xC0000409`故障证据。
5. **系统和特殊存储**：Windows系统目录、`WinSxS`、注册表、驱动、虚拟机磁盘、WSL的`ext4.vhdx`、Docker卷/数据库、页面文件、休眠文件、回收站。系统缓存走微软正式清理机制，不直接删除系统组件。
6. **特殊文件关系**：junction/reparse点/符号链接不跟随，硬链接不误算重复空间；锁定、活动进程占用、所有权不明、含未识别敏感/独有内容的目录，跳过并注明原因。不能扩大到链接目标路径。

**硬保护用例必须测试**：创建`AGENTS.md`、`agent.md`、配置MD、模拟登录资料、Cookie、API key、.git、数据库、会话目录混在同一个“可清理候选”里；验证无论是“清理空间”还是“删除该父目录”，都绝不删除或读取这些保护内容。另外验证**确实能清除验证过的第三方依赖副本中普通`README.md`等可重建文件**，避免全局`.md`拒绝规则导致600MB的依赖目录永远清不掉。保护只限当前安全清理功能；用户日后另有明确的文件编辑任务，不由本规则一概禁止合法编辑。

## 四、快清理工作流：必须限时、有结果

1. **直接按已知根目录和工具配置发现**：Windows TEMP、磁盘清理类别、受管项目缓存、npm/pip等工具提供的缓存位置及既有Tong磁盘索引。优先查看这些路径元数据；不先扫描所有C/D文件、不读私人文件正文、不开启百万文件递归任务。明确指定删除路径时只查这一路径及其必要父路径/关联引用。
2. **两档执行**：少量文件的A类直接进行有界检查+受管删除；检测到大候选时立刻返回jobId并在本机受管worker做长任务，网页单次调用不阻塞至超时。查询、取消、状态要真实可用；禁止每次把38,000文件重复哈希两遍。
3. **时间预算（验收目标）**：普通请求10秒内返回“已实际完成清理或jobId+真实阶段”；已知小缓存原则上60秒内给出删除结果。对需要持续校验的大项，每10秒内应更新真实文件数/字节或阶段检查点；连续60秒无实际进展须明确标记阻塞，不能无限挂起，超过合理资源预算必须可取消/恢复。时间预算不是跳过安全校验的理由，不能为了“过线”假报进度。
4. **任务效率**：以**最大安全回收量优先**，清过的缓存不重扫/重删；处理一批时独立受阻项跳过，继续其他获准项目。共享依赖不因文件名相同被删除；不要复制600MB的`node_modules`来证明它重复。对历史副本有可验证归档时先利用现存源哈希/锁文件和manifest，使用增量状态证据，执行前做必要且足够的防变更检查。
5. **删除阶段持续可靠**：受管worker支持`queued / scanning / verifying / ready / deleting / verifying_result / completed / blocked / cancelled / failed`，持久审计、原子进度写入、跨会话查询、幂等与撤销；删除中断后先盘点已删/未删再续，不得把半删除当成功。撤销已有授权时停止新的删除操作，不能提升权限。
6. **结果报告**：实际被删文件数和逻辑大小、D/C盘前后`freeBytes`、保护文件保留情况、跳过项目/原因、生产健康、真实任务ID及审计。**不要汇报“预计回收5GB=已回收5GB”**。用户的要求是清理效果，而不是漂亮的Plan报告。
