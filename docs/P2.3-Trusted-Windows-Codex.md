# P2.3 可信 Windows Codex 执行器

## 执行边界

默认仍为 `isolated`，原 `TongWorkerBroker` 保留且没有可用的隔离启动器时拒绝真实执行。只有本机配置文件 `runtime/trusted-codex.json` 明确启用后，任务管理器才选择 `trusted-windows`。公网 MCP 仍只暴露原有的 `tong_agent_*` 工具，不能修改可信配置、指定可执行文件、Shell、启动参数或环境变量。

可信任务同时需要：项目登记且可用、现有 `agent.execute` 授权、独立可信项目授权，以及本机对每次任务原文的批准。批准与任务 ID、项目、路径、任务、范围、会话和继续消息绑定，只能使用一次。Codex App Server 固定通过绝对路径的 `codex.exe` 以 `app-server --listen stdio://` 启动，采用现有 `workspace-write` 沙箱和 `on-request` 批准策略；所有 App Server 的额外权限请求仍被拒绝。运行中撤销项目、关闭或紧急停止会请求中断该任务。

可信模式使用当前 Windows 用户的身份和 Codex 配置。它与日常手动 Codex 是两条不同的启动与授权路径，但**不是 Windows 安全主体隔离**。本机配置文件和项目授权不能阻止同一用户身份的进程在操作系统层访问其他可读写位置。逐任务批准是执行前的硬门槛，无法保证 Codex 在批准后只执行描述中的低影响操作。因此首次真实执行仅应使用合成项目和可审查任务；高影响任务要由本机人员审查并独立配置必要的 Codex 权限。本阶段不自动提升沙箱设置。

任务管理器在同一进程内限制总并发，并让同一项目串行。`runtime/agent-tasks.json.manager.lock` 阻止多个任务管理器同时改写任务持久化文件；进程退出后，下一次启动会按锁内 PID 验证并回收已退出管理器的锁。可信 Broker 另用 `runtime/trusted-project-locks/PROJECT_ID.lock` 阻止跨进程同时修改同一项目。锁内容损坏或 PID 被复用时保持拒绝状态；只有确认对应进程已停止后，才能手动移除过期锁。取消会向 App Server 发送 `turn/interrupt`，随后尝试结束直接子进程；Windows 后代进程不保证全部回收。紧急停止也遵守这个限制。

## 本机启用与回滚

以下命令只在部署后的 Tong 项目目录内、由 Windows 本机用户运行。本开发分支未部署，执行以下命令前应先完成独立验收。

```powershell
node scripts/TongTrustedControl.mjs status
node scripts/TongProjects.mjs add --id sample --name "Synthetic project" --path D:\synthetic-project --permission metadata
node scripts/TongProjects.mjs grant-agent sample
node scripts/TongTrustedControl.mjs enable --codex "C:\absolute\path\to\codex.exe"
node scripts/TongTrustedControl.mjs grant sample
```

公网 `tong_agent_start` 创建任务后，本机查看并批准具体任务：

```powershell
node scripts/TongTrustedControl.mjs task TASK_ID
node scripts/TongTrustedControl.mjs approve TASK_ID
```

撤销与停止：

```powershell
node scripts/TongTrustedControl.mjs revoke sample
node scripts/TongTrustedControl.mjs disable
node scripts/TongTrustedControl.mjs stop
node scripts/TongTrustedControl.mjs status
```

`disable` 关闭可信执行并清除未使用的任务批准。`stop` 写入独立的 `runtime/trusted-codex.json.stop` 停止标记，即使策略锁卡住也会使执行检查拒绝新任务并请求中断运行任务；下次本机 `enable` 会清除旧批准和停止标记。完整回滚时先 `stop`，再逐项目 `revoke`，保留原隔离 Broker。若任务仍有后代进程，需本机人工核查和处理。审计事件写入 `runtime/trusted-audit.jsonl`，不记录任务原文。不要修改真实运行数据库来启用模式。

## WSL2 预留

`TongExecutorRouter` 使用 `preflight`、`runTask`、`close` 接口分派执行器。将来的 WSL2 Codex 执行器应实现同一接口，并固定发行版、可执行路径、参数与 Windows/Linux 路径映射；不要把 MCP 字符串拼接成 `wsl.exe` 命令。本阶段没有安装 WSL 内第二份 Codex，没有改变 WSL 配置。Windows Codex 在获批准的任务中可沿用自身工具调用 `wsl.exe`，但可信模式不提供通用 Shell MCP 工具，也不对 WSL 命令提供独立操作系统隔离。
